## AgentScope与AutoGen

### 刹车机制
AgentScope 的 Pipeline 设计原则是 **“固化运行逻辑”**：谁先发言、什么条件下回退、最多允许几轮，都在流水线构造时由开发者确定，而不是 **交给模型临场决定**。框架本身就提供了多层刹车机制：
- **最大轮次限制**：AgentScope 的 maxIters 参数直接限制了循环轮数，它的存在就是为了防止模型“一直不停”。你提到的设置最大对话轮次，正是这个机制。
- **显式终止标记**：可以在消息协议中加入终止条件，例如要求特定 Agent 输出“〖通过〗”并附带 {"terminate": ...} 的元数据，实现智能停止。
-  **制结束保护**：在 Pipeline 外层还可以再加一层最大轮数保护，无论内部业务逻辑如何，超过 N 轮就强制结束，确保流程不会无限运转。
因此，从技术实现角度看，AgentScope 具备完整的机制来防止“卡死”。你看到的终止条件，正是它作为工程化框架的体现。

### 为什么Qingwen不选择AutoGen而选择AgentScope

#### AutoGen 是“对话驱动”的群聊模式
它的核心抽象是 ConversableAgent，智能体之间通过对话自发交互，工作流是**动态/自发**的，灵活性极高，但也意味着**行为较难控制**。当 Agent 数量增多时，对话走向可能变得难以预测，想在中间插入人工审批或规则校验会比较绕路。

#### AgentScope 是“消息驱动”的工程化平台
它的核心抽象是 Message 和 Actor，将 Agent 间的通信**显式化为可追踪的消息对象**，而不是单纯在 Prompt 里拼上下文。Pipeline 可以显式定义顺序、并行、分支等调度逻辑，控制权牢牢在开发者手中。这种设计带来了**极高的并发与扩展性**，原生支持分布式部署，适合构建工业级、可运维的大规模多智能体系统。

>对 Qingwen 这类需要**流程可控、消息可审计、易于分布式扩展**的项目而言，AgentScope 的“显式控制”哲学比 AutoGen 的“涌现式协作”更贴合生产级需求。
